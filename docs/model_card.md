# Model card: machine failure classifier

Registered model version 1, alias `champion`. All numbers come from
[results/report.json](../results/report.json) and [results/training.json](../results/training.json)
and are regenerated by `pmm train`, `pmm export` and `pmm report`.

## Purpose

Flags milling operations that are likely to end in a machine failure, from six readings that a
machine controller records anyway. The output is a score and a yes/no decision at a fixed
threshold. It is meant to prioritise inspections, not to stop a machine automatically.

Out of scope: real machines without validation on their own data, failure types other than those
in the training data, and any use of the score as a calibrated probability.

## Model

- `HistGradientBoostingClassifier` (scikit-learn, default settings, seed 0) on the six raw inputs
  plus three physical features: mechanical power, the gap between process and air temperature,
  and torque times tool wear.
- Chosen among four candidates (logistic regression and gradient boosting, each with and without
  the features) by PR-AUC on the validation split.
- Threshold 0.781, the value with the highest F1 on validation.
- Shipped as a skops bundle with the threshold, the test metrics and the drift reference. Loading
  it trusts only an explicit list of types.

## Data

AI4I 2020 Predictive Maintenance Dataset (UCI, CC BY 4.0), 10,000 synthetic operations, 3.4 %
failures. Inputs: product type (L, M, H), air temperature, process temperature, rotational speed,
torque, tool wear. The five failure-mode columns define the target and are removed before
training. Stratified split 70/15/15 with seed 0.

## Metrics

Test split, 1,500 rows, 51 failures, scored once. Intervals: 95 %, 1,000 bootstrap resamples drawn
within each class.

| Metric | Test | 95 % interval |
| --- | ---: | ---: |
| PR-AUC | 0.882 | 0.803–0.952 |
| ROC-AUC | 0.973 | 0.943–0.994 |
| Precision | 0.949 | 0.868–1.000 |
| Recall | 0.725 | 0.608–0.843 |
| F1 | 0.822 | 0.736–0.896 |

At the threshold: 37 failures found, 14 missed, 2 false alarms, 1,447 correct negatives.

| Failure mode | Detected | Recall |
| --- | ---: | ---: |
| Tool wear (TWF) | 1 of 4 | 25% |
| Heat dissipation (HDF) | 13 of 13 | 100% |
| Power (PWF) | 11 of 18 | 61% |
| Overstrain (OSF) | 16 of 18 | 89% |
| Random (RNF) | 0 of 0 | n/a |
| No mode recorded | 0 of 2 | 0% |

## Limitations

- **Synthetic data.** The failures follow fixed rules on the same quantities the features compute.
  The scores show that the pipeline works and that the physical features matter; they are not an
  estimate of performance on a real machine.
- **Few failures.** 51 test failures make every metric uncertain, recall most of all.
- **Tool wear.** These failures occur at a random wear time inside a window; the inputs cannot say
  when, and only one of four is found.
- **Unpredictable failures.** Random failures and failures without a recorded mode cannot be
  predicted from the inputs and set a ceiling on recall.
- **No calibration.** At 3.4 % prevalence almost every score is close to 0. Use the score to rank
  and the threshold to decide.

## Monitoring

- `/drift` compares a batch of at least 500 readings with the training distribution per feature
  (population stability index; warning from 0.1, alert from 0.25). On the test split every feature
  stays below 0.01; a torque offset of 8 Nm raises an alert at 0.59. Smaller batches are rejected,
  because at 100 readings sampling noise alone made at least one feature warn in 91% of batches
  without drift.
- The drift reference is a random sample of the training rows. Batches of consecutive readings
  differ from it when an input changes slowly: five blocks of 1,000 rows in file order each raised
  an alert for air and process temperature, which follow a random walk in AI4I.
- `/metrics` exposes request counts and latency, the number of scored readings and predicted
  failures, and the PSI of the last drift batch, for alerting in Prometheus.
- Drift covers only the inputs. Detecting a drop in accuracy needs labelled outcomes and a
  scheduled comparison, which this project does not include.

## Operation

- Retraining registers a new version; the alias moves only if validation PR-AUC is at least as good
  as the current champion's.
- The threshold trades missed failures against false alarms. It is chosen by F1 here; in
  operation the cost of each error type should decide it. It is stored next to the model in the
  bundle, so moving it would not need a new model.
- The API rejects unknown fields, physically impossible values and batches over 1,000 readings,
  and does not log readings or predictions.
